# PolyU Canvas study workspace

- The standalone Apple Silicon application is in `MacApp/`; its web dashboard and read-only Canvas pipeline are in `学习控制台/`. Build version 1.8.1 with `MacApp/build.py` using the Python executable from `load_workspace_dependencies`. Release DMG/ZIP files are in `Mac发布/`.
- Version 1.8.1 has no weekly reports, weekly plans, coach CLI, project-side Canvas profile, or project-side course-material archive. The dashboard shows deadlines, grades, recent Canvas changes, and document evidence directly.
- The application is a university-wide empty framework: no default course roster, personal course data, automatic imports, priorities, or preconfigured assessment weights. The explicit build allowlist must never include account data, Canvas cookies/tokens, raw snapshots, course materials, or personal grading schemes.
- The Mac app targets arm64 and macOS 13 or later. It uses AppKit/WebKit for its window and school login. Its data lives only in `~/Library/Application Support/PolyU study控制台/account/`; the first 1.5 launch migrates an authenticated 1.4 account, removes the old weekly output, and preserves login, manual arrangements, document cache and grade evidence.
- `native_canvas.py` is a read-only session adapter. The login window exports only cookies applicable to `canvas.polyu.edu.hk`; authenticate the current user from a signed-in Canvas page before committing a session, with `/users/self` only as an available fallback. Reject a different user ID until the previous account has logged out. Native session/logout endpoints require the per-process native secret; ordinary mutations retain Origin and CSRF checks.
- App logout stops the backend and sync workers before deleting the entire app data directory and clearing WebKit login data, open windows and in-memory account data. Return to an empty framework and collect again only after a fresh login. Do not retain an account backup on logout.
- `canvas_sync.py` reads the authenticated All Courses page and dashboard cards for the complete current course roster, then attempts assignment and announcement data. A partial Canvas endpoint failure must remain visible and must not block document scanning. The dashboard listens only on `127.0.0.1`.
- `canvas_archive.py` reads authenticated course Modules pages, follows visible course-page links, and downloads every discovered attachment before `canvas_documents.py` interprets files. Module attachments use their `Attachment_<fileId>` markup and are saved in `documents/files/<course>/<module>/<filename>`. Files found only on pages go in a separate clearly named folder. Save text extracted from visited course pages under `documents/web/` for the subsequent recognition phase; do not cache login scripts or tokens. The manifest reports completed and failed downloads separately and must never claim to cover inaccessible/unlisted files. File reading uses `document_text.py` and the bundled native `DocumentReader` (PDFKit/Vision). Record unsupported, locked, failed, partially readable files and failed enumerations visibly.
- The downloaded file tree, text/cache, download manifest and evidence ledger belong exclusively under the app profile's `documents/` directory. `course_evidence.py` retains Canvas URLs, filenames, pages/locators and original excerpts for dates and weights. Cache only within the authenticated account; logout deletes the entire cache with the app profile. File download redirects may target approved HTTPS Canvas storage domains, but cookies/authorization must never follow off the school's Canvas host.
- `assessment_reader.py` interprets assessment sections and timetable rows, associates separated notice titles/dates/times/venues, distinguishes project milestones, and keeps OCR confidence per row. Extract all text/tables before the image pass, publish findings progressively, and reprocess this same account's saved files on interpreter upgrades. Course assessment weights must be distinguished from rubrics, bonus marks and case-study statistics. Do not invent dates from scientific quantities or standards numbers. Show unpublished dates separately from genuine source conflicts; blank/image-only pages successfully processed are not manual-review tasks.
- `document_deadlines.py` reconciles app-derived file deadlines with Canvas due dates and personal arrangements. Date ambiguity and conflicts remain pending. Only entries previously generated by the retired scanner may be removed during migration; preserve independent manual source notes.
- File grading weights must form a coherent 100% scheme, with unambiguous assessment matching, before folding published numeric scores. File/file or file/Canvas weight conflicts leave the fold blank and retain both sources. Explicit equal per-item weights can contribute graded items independently; expected assessment counts must be respected. Unknown weights, future/ungraded assessments, ambiguous matching, complex or hidden totals remain blank. Canvas's published current score is shown separately from document-based folds.
- Use the original official PolyU assets in `学习控制台/assets/`, with URLs recorded in `SOURCES.txt`; preserve proportions and colors. No invented logo or cap icon. Version 1.8.1 appears in Settings, native About panel and arm64 DMG/ZIP filenames. The dashboard footer reads `来源：Canvas`.
- Bundle pinned pdfplumber dependencies via `MacApp/document-vendor-lock.json`; `pdf_layout.py` reconstructs PDF tables locally. Keep original dependency licenses and arm64-only binaries.

- Version 1.8 uses four everyday navigation entries and an on-demand Settings dialog with an explicit close button. Login/logout, document recognition, course overview and diagnostics appear inside Settings; version appears there and in native About.
- Diagnostic events accept only fixed event/result/error identifiers. Authorized-account logs roll at 200 events in account/diagnostics; anonymous and completed logout events remain in process memory. Logout deletes all account logs, with no cross-account history or credentials/body text.
- Final exams are a separate category across documents, Canvas, manual schedules and filters. Final projects/reports remain assignments; mixed exam names remain general tests unless the original evidence identifies separate items. Evidence version 8 reinterprets this account's saved files.
