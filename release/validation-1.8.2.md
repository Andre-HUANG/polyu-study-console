# 1.8.2 验收与覆盖边界

正式发布要求源码干净、主分支同一提交的安全检查、Python 回归、Mac 原生验收、Windows 原生验收及发布校验全部成功。validation.json 与 GitHub Actions 保存相同源码提交和安装包哈希；未通过门禁的产物不能发布为正式版。

本次 Mac 离线回归为 202 项，网络访问尝试为零；31 项实际回环 HTTP 检查覆盖授权、Origin、CSRF、账号隔离、完整／精简响应及 ETag。Windows 按平台跳过 Mac 专用测试，具体数量由该平台日志记录。

原生验收运行真正的 AppKit／WebKit 和 WebView2 程序，检查宽窄布局、设置、版本、原生桥接、重启、关闭及隔离账号退出清理。Mac Keychain 与 Windows DPAPI 分别验收。隔离测试不访问真实账号。

更新演练使用锁定 Sparkle 2.10.0／WinSparkle 0.9.4 和一次性测试签名密钥：Mac 包含升级、错误签名、损坏包、断网、启动失败回退及取消更新后的回退标记清理；Windows 包含便携版上述五项和安装版升级。Windows 调用生产安装助手，Mac 调用生产回退逻辑；旧程序写入排空使用受控夹具，成功升级启动实际新版原生程序。失败演练使用缩短的等待时间，PID 观测只用于回收测试程序。权限／替换失败、磁盘空间不足及安装中断后的程序恢复注入属于隔离验证，不能当作所有系统权限提示的真实验收。

发布签名工具另用一次性密钥实际生成三个更新源和元数据签名，验证修改更新源、修改安装包均被拒绝。正式公钥随程序内置，私钥只在系统 Keychain／受控 GitHub 发布环境保存。

真实学校服务验收记录保留在本机，不在公开报告中披露账号派生信息。公开 CI 使用隔离合成账号，不能代替学校会话验收；应用必须区分未发布的课程日历、服务不可用和文档读取限制。

课程表来源冲突、班组歧义、周次基准不明及低置信度保留待确认；确认安排保留原证据。学校考试期只作校历提示；Canvas 作业截止日期不作为考试开始时间。

程序更新与回退不备份、不回退账号资料。程序更换范围仅限应用程序包。Mac 为 ad-hoc 签名且未 notarize，Windows 无 Authenticode；应用内 Ed25519 更新验证与这些系统签名是不同的验收项目。

性能原始数据和未达目标见 performance-1.8.2.md / .json。Windows 真实学校 SSO、用户本人电脑的 Windows 升级及物理电池耗电不在本机实测范围。
